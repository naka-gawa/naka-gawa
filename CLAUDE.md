# Overview
This is a personal portfolio repository (`naka-gawa/naka-gawa`). 
It periodically generates and automatically updates a 3D contribution calendar (`yoshi389111/github-profile-3d-contrib`) displayed on the GitHub Profile using GitHub Actions.

# Architecture and Security Design
The automation workflow of this repository is designed with security as the highest priority, particularly focusing on the protection of affiliated Organization data. AI assistants must not suggest any changes that deviate from this design philosophy (e.g., expanding the scope of a Personal Access Token).

## 1. Data Reading (Secure Retrieval of Org Contributions)
- **Constraint**: To prevent external tools from reading source code or metadata of affiliated Organizations, Classic PATs with the `repo` scope or Fine-grained PATs with broad access scopes will **never be used**.
- **Solution**: By enabling "Include private contributions on my profile" in the GitHub UI, the workflow safely retrieves only the "contribution blocks" (activity volume), which includes Organization activities, using only the default `${{ secrets.GITHUB_TOKEN }}` (Read-only).

## 2. Automated Commits and PR Creation (Utilizing GitHub Apps)
- **Constraint**: Because Branch protection (`Require a pull request before merging`) is enabled, GitHub Actions will not push directly to the `main` branch.
- **Solution**: A dedicated GitHub App is created. The workflow uses this App Token to automatically create a Pull Request from the file diffs and merge it automatically (`gh pr merge --auto`). This achieves automation while preventing unauthorized Action executions from external sources.

## 3. Mandatory Commit Signatures (GPG)
- **Constraint**: Branch protection (`Require signed commits`) is enabled.
- **Solution**: Automated commits made via the GitHub App are signed using a GPG key.

# Required Secrets
The following Secrets are registered in the repository for GitHub Actions to function correctly. Do not change these variable names when modifying the workflow code.

- `APP_ID`: App ID of the GitHub App used for creating PRs.
- `APP_PRIVATE_KEY`: Private key (.pem) of the GitHub App used for creating PRs.
- `GPG_PRIVATE_KEY`: GPG private key for commit signing.
- `GPG_PASSPHRASE`: Passphrase for the GPG private key.
- `APPROVE_PR_PRIVATE_KEY` (secret) / `APPROVE_PR_APP_ID` (variable): Credentials of the single **approver** GitHub App (one App per purpose) used by `approve-automated-pr.yaml` to request approval of automated (bot) PRs from the `approve-pr-server` repository (`csm-actions/approve-pr-action` Client/Server model). The App holds `issues: write` + `pull requests: read` + `contents: read` but **no** `pull requests: write`, so it cannot approve by itself. The approving PAT is **not** stored in this repository — it lives only in the `approve-pr-server` repo. This keeps the token policy above intact (no broad-scope PAT here). See `docs/required-status-check.md`.

# Directory Structure and Artifacts
- `.github/workflows/`: Contains the definitions of the automation workflows.
- `profile-3d-contrib/`: The output directory for SVG images automatically generated by Actions (manual editing is not required).
- `README.md`: The main profile page, which references the images located in the `profile-3d-contrib/` directory.

# Commit Convention & Git Workflow Rules

This repository strictly follows **Conventional Commits** for commit messages. AI assistants (like Claude, Copilot) generating code, PRs, or commit commands must adhere to these rules to maintain a clean and automated Git history.

## 1. Commit Message Format
Commit messages must have the following structure:
`<type>[optional scope]: <description>`

**Allowed Types:**
- `feat`: A new feature (e.g., adding a new section to the README)
- `fix`: A bug fix
- `docs`: Documentation only changes (e.g., updating this CLAUDE.md or README.md)
- `style`: Changes that do not affect the meaning of the code (white-space, formatting)
- `refactor`: A code change that neither fixes a bug nor adds a feature
- `test`: Adding missing tests or correcting existing tests
- `chore`: Changes to the build process, CI/CD, or auxiliary tools and libraries

**Example:**
- `docs: update tech stack in README`
- `chore: update github profile 3d contrib` (Used by the automated GitHub Actions bot)

## 2. Git Workflow Constraints
When suggesting Git commands or shell scripts to the user, strictly keep the following repository constraints in mind:

1. **No Direct Pushes to `main`**: Branch protection is enabled (`Require a pull request before merging`). Do not suggest `git push origin main`. Always suggest creating a new branch and opening a PR.
2. **Mandatory GPG Signing**: Branch protection (`Require signed commits`) is enabled. All commits must be signed. When providing git commit commands, assume the user's local environment is configured for signing, or explicitly use the `-S` flag (e.g., `git commit -S -m "docs: update readme"`).
3. **Automated PRs**: The daily profile 3D calendar update is handled automatically by a GitHub App token via Actions. Do not modify the automated commit message (`chore: update github profile 3d contrib`) in the workflow file.
